# Специфікація v2 — уточнення від власника (05.10.2026)

Зібрано з розмови. Джерело правди по бізнес-логіці. Статуси: ✅ зроблено · 🔨 будую · 📋 заплановано · ❓ потребує уточнення.

## 1. Потік акаунта і групи AdsPower → етапи дашборда

```
Автозавод/Автореги (заведені)  →  Прогрев (warmup)  →  Готовий (ready)
     Готовий далі два напрямки:
        (а) ОРЕНДА: шарим доступ → видаємо команді, ставимо мітку команди (issued + team)
        (б) ПРОДАЖ: → Продано (sold)   ← окремий напрямок, фіксується
```

| Група AdsPower | Етап дашборда | Нотатка |
|---|---|---|
| Автореги / Автозавод | пул (`purchased`/`in_adspower`) | перші акки → на прогрів |
| Прогрев | `warmup` | |
| **Готовий** (створюємо групу) | `ready` | коли акк готовий — дашборд переносить профіль у групу «Готовий» 📋 |
| Команди: CPA Samurai Team 298, Budget Samurai Team 300, Clover Group 297, Dani | `issued`, група = команда/клієнт | «віддали в роботу типам»; сигнал — зміна назви профілю |
| **Продано** | `sold` (новий) 🔨 | термінальний, окремий напрямок |
| **Кінги** | особливий керований пул 📋 | вибрані акаунти: тягнемо статку, аналітику, синхр. з платіжками; доступи для клієнтів беруться ЗВІДСИ |
| ffff / Автозавод / finansist | тимчасові робочі | нейтрально → `in_adspower`, група зберігається |


## 2. Продаж (новий напрямок) — 🔨 будую зараз
- Новий етап `sold` (досяжний з warmup/ready/issued/… , термінальний).
- Запис продажу: кому продали (`sold_to`), ціна (`sale_price`), дата (`sold_at`).
- Фінанси: виручка з продажів окремим рядком поряд з комісією за оренду.

## 3. Група «Кінги» — керований пул для клієнтів — 📋
- Вибрані акаунти переносяться в «Кінги».
- По них: тягнути статистику (спенд/оголошення), розкидати в аналітику, синхронізуватись з платіжками (FBM).
- **Доступи для видачі клієнту беруться з групи «Кінги»** (див. п.5).

## 4. Імпорт: додати проксі — 📋
- На сторінці «Імпорт замовлення» — поле проксі (type/host/port/логін/пароль), застосовується до профілів партії (замість `no_proxy`).

## 5. Запити на акаунти + видача доступу клієнту — 📋
- При запиті на акаунти — **сповіщення** про запит.
- Клієнт надає ID свого кабінета (Business Manager) — або в дашборді показуємо ID кабінету при запиті.
- Кнопка **«Розшарити доступ»** → бере акаунт із групи «Кінги» і шарить клієнту (механізм: **додавання BM клієнта партнером у самому FB** — через проксі/сесію акаунта; токен акаунта є в order-файлі).

## 6. КРИТИЧНО: проксі акаунта для отримання даних — 📋 (архітектурне)
- **Будь-яке отримання інфи з FB-акаунта має йти через проксі САМОГО акаунта** (бо FB прив'язує сесію до IP; запит з іншого IP = ризик бана/чек-поінта).
- Отже прямі запити до FB (ads/статус/спенд) робимо або через відкритий профіль AdsPower (у нього вже є проксі), або маршрутизуючи HTTP через проксі акаунта з його cookies.
- Впливає на дизайн збору даних: статка з акаунтів іде через bridge/AdsPower, не напряму з сервера.

## Порядок робіт
1. 🔨 Продано (`sold`) + запис продажу + фінанси.
2. 📋 Імпорт з проксі.
3. 📋 Повний імпорт 606 профілів з мапінгом груп → етапи/команди + автосинхронізація; авто-перенос у групу «Готовий» при `ready`.
4. 📋 Кінги як керований пул + збір статки через проксі акаунта.
5. 📋 Запити + «Розшарити доступ» з групи Кінги + сповіщення.
