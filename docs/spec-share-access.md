# План: «Розшарити доступ» (додати BM клієнта партнером)

Мета: за запитом клієнт дає ID свого Business Manager → оператор тисне «Розшарити доступ» → акаунт із групи «Кінги» ділиться з BM клієнта (партнерство у FB), усе фіксується.

## Ключові рішення (узгоджені)
- «Доступ» = **додати BM клієнта партнером у самому FB** (не share-profile AdsPower).
- **Токен акаунта не зберігаємо в БД** (§4). Він уже лежить у **remark AdsPower-профілю** (поле «Токен…», ми його туди пишемо при імпорті). З токеном працює **тільки bridge**, і **через проксі самого акаунта**.
- Доступи беруться з акаунтів **групи «Кінги»**.

## Що таке «партнерство» у FB (механізм)
Акаунт (наш) володіє BM і рекламним кабінетом. Щоб клієнт керував рекламою, його BM додається **партнером** до нашого рекламного кабінету з роллю (напр. advertiser/analyst). Робиться це:
- **Вручну**: Business Settings → Partners → Add partner → ID BM клієнта → обрати кабінет + права. (ТЗ §1: дію у FB робить людина, система фіксує.)
- **API** (Graph API, партнерський/agency-ендпоінт) з токеном акаунта — точний ендпоінт звіряємо при реалізації (версія Graph API змінюється).

## Дані (модель)
- `clients.bm_id` — Business Manager ID клієнта (він надає).
- `requests` — додати `client_bm_id` (ID кабінету з конкретного запиту, якщо інший).
- Нова таблиця `access_shares`: `account_id`, `client_id`, `client_bm_id`, `ad_account_id` (що ділимо), `role`, `status` (pending|shared|revoked|error), `shared_by`, `shared_at`, `result`.

## Покроковий флоу (UI)
1. Клієнт просить акаунти → **заявка** → **сповіщення** (вже є).
2. У заявці оператор бачить/вводить **BM ID клієнта** (або беремо з картки клієнта).
3. Кнопка **«Розшарити доступ»**: система пропонує акаунт(и) з групи **«Кінги»** (готові, з кабінетом).
4. Підтвердження → створюється запис `access_shares` (pending) і **апрув адміна** (як на видачі).
5. Виконання (одна з двох фаз нижче) → статус `shared`, подія в журнал, акаунт позначається як виданий цьому клієнту (`issued` + мітка/група клієнта).

## Реалізація — дві фази

### Фаза 1 — безпечний MVP (без дії у FB, будуємо хоч зараз)
- Усе з флоу вище, але **саме додавання партнера оператор робить руками** в AdsPower-профілі (відкрив → Business Settings → додав BM). 
- Система: показує оператору ID кабінету й BM клієнта, дає кнопку «Відкрити профіль» (bridge `open_profile`), фіксує факт і час (`access_shares`=shared вручну), шле клієнту підтвердження.
- **Нуль ризику бана від автоматизації; нічого не зберігаємо зайвого.** Тестується без реальних дій у FB.

### Фаза 2 — автоматизація через bridge (потребує тесту на FB-0014)
- Серверна команда `share_bm_partner` з args: `account_id` (→ profile_id), `client_bm_id`, `ad_account_id`, `role`. **Без секретів у args.**
- **Bridge**: читає токен акаунта з remark профілю (AdsPower Local API `user/list`), бере проксі профілю, і робить Graph API виклик партнерства **через цей проксі**. Повертає результат. Сервер токен не бачить/не зберігає.
- Апрув адміна обов'язковий (як усі дії запису через агента/bridge).
- Ризики: токен із order-файлу може бути простроченим/вузьким за правами → може знадобитись свіжий токен з активної сесії профілю (складніше). Точний Graph-ендпоінт і права звіряємо на FB-0014.

## Відкриті питання
- Яку роль давати клієнту (advertiser / analyst / full)?
- Ділимо **рекламний кабінет** чи **сторінку+кабінет**?
- Токен з order-файлу достатній для партнерства, чи потрібен свіжий (через відкриту сесію профілю)?
- Один акаунт на клієнта чи кілька за запит?

## Рекомендований порядок
1. **Фаза 1** (флоу + фіксація + ручна дія) — зараз, безпечно.
2. **Фаза 2** (bridge + Graph API) — коли підтвердимо ролі/ендпоінт і протестуємо на FB-0014.
